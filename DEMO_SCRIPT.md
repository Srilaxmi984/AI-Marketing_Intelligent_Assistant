# Demo Runbook (2–5 minutes)

This script is designed for a live screen recording of the application auditing the selected target, HubSpot. The audit can take around a minute depending on network conditions and may return partial results if a configured time or link-check cap is reached.

## Before recording (Windows PowerShell)

Open PowerShell in the repository folder:

```powershell
cd C:\path\to\AI-Marketing_Intelligent_Assistant
```

Install dependencies once:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If PowerShell blocks activation, use the environment's Python directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Otherwise, with the environment activated, start the server:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open **http://127.0.0.1:8000/** in the browser. Keep the server terminal visible in the background. Do not run `scripts/verify_live.py` at the same time: that helper binds its fixture server to port 8000 and can conflict with the web app.

## Screen-recording narration (about 3 minutes)

**0:00–0:25 — Introduction**

“Hello. This is my AI Marketing Intelligence Assistant. It audits a product website for technical SEO and AI-search readiness. I selected HubSpot because it is a real marketing website with a mix of product, company, and content pages, which makes the audit more meaningful than testing only a sample page.”

**0:25–0:50 — Start the audit**

“The interface accepts a website URL and a maximum page count. I’ll use the selected HubSpot URL and the default 25-page sample, then start the audit. The backend validates the URL before making requests, including checks intended to prevent access to private or restricted network addresses.”

Action: show the URL and page limit, then click **Start Audit**. Allow the request to finish; do not cut away before the result appears.

**0:50–1:35 — Explain the overall score and metrics**

“The crawler discovers internal pages and collects their HTML. The application then evaluates five metrics. The first two are required by the assignment: title and meta description lengths, and broken internal links. The three additional metrics are indexability and canonicalization, AI crawler access through robots.txt, and Schema.org structured data.”

“The overall score is calculated by Python using configured metric weights. It is not generated by the language model.”

Action: point to the overall score, then scroll through the five metric cards and show the status, score, summary, and pass rule. Expand a detail table where useful.

**1:35–2:15 — Explain the action list**

“After the metrics are calculated, the application sends sanitized findings to Gemini to generate prioritized actions for a marketer. The model does not receive permission to change the scores. Its proposed output is validated, including the metric identifiers and affected URLs. When the API key is absent, the service is unavailable, or the response fails validation, a deterministic fallback produces the action list.”

Action: show the action source badge, recommendation priority, business impact, evidence, and sample affected URLs. If the badge says FALLBACK, explain that fallback is an intentional reliability feature, not a failed audit.

**2:15–2:40 — Show transparent details**

“The dashboard also lets us inspect the complete structured JSON response. This makes the API output auditable and suitable for integration with other marketing tools.”

Action: expand **View Complete JSON Audit Response** and briefly show the crawl stats, metric values, score formula, actions, and warnings.

**2:40–3:00 — Close**

“The project includes automated tests for valid and invalid inputs, crawler behavior, parsing, metrics, link checking, LLM validation, and security. The main limitations are that crawling is synchronous, JavaScript-rendered content is not evaluated, and internal link checking is capped to protect the target site. Thank you.”

## After recording

- Keep the video between 2 and 5 minutes.
- Make sure the final score and all five metrics are readable.
- Include the action list and the JSON expansion.
- Save the recording as `demo.mp4` and add it to the repository only if its size is reasonable; otherwise submit the video separately as instructed.
- Do not claim a specific live score unless that exact score appears in the recording. The saved `RESULTS.md` report is a recorded run and live results can change.
